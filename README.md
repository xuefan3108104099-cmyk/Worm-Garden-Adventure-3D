# Worm's Garden Adventure 3D

Coursework project **GEIAL31L-B2a** - a 2D maze game converted into a **3D game
rendered by a hand-written software rasteriser**.

Every pixel is produced by our own NumPy code: there is **no PyOpenGL, no
moderngl, no Panda3D / Ursina / PyBullet and no 3D engine of any kind**.
Pygame is used only for the window, the event loop, the HUD text and the
`pygame.draw.line` overlay of the wireframe debug view. Pillow is used only to
generate the texture bitmaps and to save PNG screenshots.

## 2. Running

```powershell
python main.py            # the game (1280x800 window, FAST render preset)
python first_cube.py      # milestone demo M1-M4: one textured cube
python -m unittest discover -s tests -v      # 19 unit tests
python tools\make_figures.py                 # rebuild all report figures
python tools\perf_bench.py                   # rebuild the performance table
python tools\record_demo.py                  # rebuild the demo video (needs ffmpeg)
```

The demo video `screenshots/demo.mp4` (2 min 9 s, 1280x800) is generated by
`tools/record_demo.py`, which drives the real `App` loop head-lessly and writes
raw frames into ffmpeg, so what you see in the video is what the game draws.

`main.py` also accepts automation flags (used for the screenshots):

```powershell
python main.py --frames 6 --shot screenshots\fig11_hud.png --preset 1 --walk nene
```

| flag | meaning |
|------|---------|
| `--frames N` | render N frames and quit (head-less friendly) |
| `--shot FILE` | save a PNG before quitting |
| `--preset N` | 0 FAST, 1 BALANCED, 2 HIGH, 3 NATIVE |
| `--walk STR` | scripted walk, e.g. `nene` = forward, left, forward, left |

For a completely head-less run set `SDL_VIDEODRIVER=dummy` first.

## 3. Controls

| key | action |
|-----|--------|
| **W A S D** | move the worm (world axes: W = -Z, S = +Z, A = -X, D = +X) |
| **SPACE** | jump (gravity 10 u/s², initial speed 3.2 u/s) |
| **P** | toggle perspective / orthographic projection |
| **1 / 2 / 3** | camera presets: elevated, side, follow |
| **Q / E** | orbit the camera around the maze (or the worm in follow mode) |
| **mouse wheel** | zoom in / out |
| **T** | toggle bilinear texture filtering (Part B) |
| **G** | toggle distance fog (Part B) |
| **F1** | wireframe overlay (draws every rasterised triangle edge) |
| **F2** | normal visualisation (RGB = n.x, n.y, n.z) |
| **F3** | depth buffer visualisation (near = bright) |
| **F5** | cycle render resolution (480x300 / 640x400 / 896x560 / 1280x800) |
| **R** | restart: new maze, score and level reset |

Goal: collect 4 apples, then reach the flag. A flag reached with fewer than 4
apples sends the worm back to the start. Water holes kill (restart the level).

## 4. Project structure

```
config.py       all constants: maze size, physics, camera, lighting, fog,
                the four render-resolution presets
math3d.py       vectors, 4x4 matrices, camera basis, world->camera,
                perspective / orthographic projection, near-plane clipping
maze.py         the original DFS maze generator (unchanged rules) plus
                3D cell centres, wall-run merging and circle/box collision
mesh.py         box, sphere, quad, tiled floor, wall meshes, merge/transform
textures.py     9 procedural textures (Pillow) + nearest / bilinear sampling
camera.py       orbit camera, three presets, fit-distance bisection
frustum.py      six-plane viewing frustum, AABB culling
raster.py       the renderer: transform, cull, clip, project, barycentric
                rasterise, z-buffer, perspective-correct UV, lighting, fog
particles.py    3D particle system (collect sparkles, goal firework)
game.py         game state, level building, chunked walls, collision, physics
scene.py        scene assembly (draw order: floor -> water -> walls -> props)
hud.py          screen-space HUD (level, score, apples, time, FPS, debug panel)
main.py         pygame window, input, fixed-timestep update, present/letterbox
first_cube.py   milestone demo M1-M4 with printed 4x4 matrices
tests/          unittest suite for the maths, maze and z-buffer
assets/         the generated texture bitmaps (also written at start-up)
screenshots/    all figures used in the report + the demo video
docs/           the two course documents, the bilingual task guide and the
                extracted text of both documents
tools/          figure, benchmark, recording and profiling helpers
report/         the 8-page English report (PDF)
```

Additional documents:

* `report/Worm_Garden_3D_Report.pdf` - the 8-page report.

## 5. What is implemented (checklist)

Part A - core (70 marks)

* [x] Vector maths: dot, cross, length, normalise, rotate
* [x] 4x4 matrices: translation, rotation X/Y/Z, scale, multiply, invert-by-basis
* [x] View matrix from an orthonormal camera basis; world -> camera space
* [x] Perspective projection with a configurable focal length and FOV
* [x] Orthographic projection (switch with **P**)
* [x] Triangle rasteriser with barycentric coordinates and a z-buffer
* [x] Back-face culling + near-plane clipping
* [x] Per-triangle flat shading from a single directional light
* [x] Texture mapping with perspective-correct UV interpolation
* [x] Floor, walls, apples, birds, worm, water, flag built from meshes
* [x] The 2D game logic (maze, collision, enemies, scoring) preserved
* [x] HUD, camera presets, orbit/zoom, resolution switching
* [x] Wireframe / normal / depth debug views
* [x] 19 unit tests, README, report, screenshots

Part B - extensions (30 marks, at least two, one graphical)

* [x] **Distance fog** (`G`): linear fog blended per pixel between
      `fog_start` and `fog_end`, both derived from the camera distance
* [x] **Bilinear texture filtering** (`T`): 4-tap weighted sampling, switchable
      at run time against the nearest-neighbour reference
* [x] **Frustum culling of wall chunks**: the maze walls are split into 4x4-cell
      chunk meshes, each with an AABB tested against the six frustum planes
      (24 chunks -> typically 8 are drawn in follow view)
* [x] **Four render-resolution presets** with letterboxed up-scaling
* [x] **Particle system** (3D billboard-free point sprites with size attenuation)

## 6. Performance (measured on this laptop, `tools/perf_bench.py`)

| resolution | camera | ms / frame | FPS | triangles |
|-----------|--------|-----------:|----:|----------:|
| 480x300 (FAST) | elevated | 141 | 7.1 | 989 |
| 480x300 (FAST) | follow | 163 | 6.2 | 306 |
| 640x400 (BALANCED) | elevated | 205 | 4.9 | 1059 |
| 640x400 (BALANCED) | follow | 237 | 4.2 | 313 |
| 896x560 (HIGH) | elevated | 244 | 4.1 | 1145 |
| 896x560 (HIGH) | follow | 402 | 2.5 | 317 |
| 1280x800 (NATIVE) | elevated | 301 | 3.3 | 1199 |
| 1280x800 (NATIVE) | follow | 819 | 1.2 | 322 |

The renderer is pure NumPy in a Python loop over triangles, so the cost is
dominated by the fixed overhead of ~40 NumPy calls per triangle, not by fill
rate. That is why the game starts in the FAST preset.

## 7. Known limitations

* Frame rate is low at high resolutions (see above); FAST is the default.
* Shadows, transparency and mip-mapping are not implemented.
* The texture filter comparison figure uses a dedicated grazing-angle quad so
  the difference between nearest and bilinear is easy to see.
* Only one directional light; no specular term.

## 8. Third-party code

All rendering, maths and game code in this repository is written by the author.
